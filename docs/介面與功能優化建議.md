# 紀念日提醒 App 介面與功能優化建議

## 文件目的

本文件依目前程式碼與既有使用說明，盤點 App 的介面、操作流程與功能缺口，並提出可分階段執行的優化方向。對應的可執行工作與驗收條件整理於 [`優化待辦事項.md`](優化待辦事項.md)。

## 現況摘要

目前版本已具備以下 MVP 能力：

- 建立、編輯與刪除紀念日。
- 支援不重複、每月與每年重複規則。
- 支援選填時間、分類、事件識別色與固定時區。
- 依下一次發生時間排序，並顯示倒數或已經過時間。
- 支援淺色、深色、跟隨系統及自訂主題色。
- 以 DataStore 儲存本機資料。
- 提供桌面小工具顯示最近的紀念日。

目前的產品名稱雖為「紀念日提醒」，但尚未實作系統通知、提前提醒或背景排程；現有提醒能力主要是 App 內倒數與桌面小工具。

## 優先級定義

| 優先級 | 定義 | 建議時程 |
| --- | --- | --- |
| P0 | 可能造成資料遺失、結果錯誤或使用者誤判，應優先修正 | 下一個修正版 |
| P1 | 影響核心產品價值與主要操作流程 | 下一個功能版本 |
| P2 | 改善可用性、無障礙、Widget 與維護品質 | 核心流程穩定後 |
| P3 | 擴充型功能或進階體驗 | 依使用者回饋排程 |

## 介面優化建議

### 1. 重整主畫面的資訊層級與操作入口（P1）

**現況與問題**

- 頂部工具列同時放置設定與「將 App 移到背景」，後者與 Android 系統 Home 行為重複，也不是使用者管理紀念日的核心操作。
- 清單只能依下一次到期時間顯示；項目增加後，缺少快速尋找與篩選方式。
- 卡片同時顯示日期、名稱、時間、重複方式、分類與倒數，在窄螢幕或大字體下容易擁擠。

**建議方案**

- 移除「移到背景」按鈕，把頂部空間改為搜尋或更多選單。
- 在工具列下方加入分類、即將到來、已過期等篩選條件，並保留清除篩選的入口。
- 讓卡片的主要視覺焦點固定為「名稱、下一次日期、倒數」；分類與重複方式改為次要資訊，可在空間不足時換行。
- 將已過期且不重複的事件獨立成可收合區段，避免干擾即將到來的項目。
- 可考慮加入「未來 7 天」或「本月」區段，讓近期事件更容易辨識。

**預期效益**

- 降低資訊密度，改善掃讀速度。
- 當資料量增加時仍能快速找到指定項目。
- 讓最常用操作比非典型的系統操作更容易到達。

### 2. 改善新增與編輯流程（P0-P1）

**現況與問題**

- 編輯欄位與目前頁面只使用一般 `remember` 狀態，旋轉螢幕、Activity 重建或程序被回收時可能遺失草稿。
- 儲存操作送出後畫面立即返回，沒有儲存中、成功或失敗狀態。
- 返回時不會提示尚未儲存的變更。
- 刪除時會先回到主畫面再顯示確認視窗；若取消刪除，使用者無法回到原本編輯內容。
- 日期與時間使用傳統 Android Picker，深色模式與 Compose 主題可能不一致。

**建議方案**

- 使用可保存狀態的表單模型，讓草稿可跨組態變更與程序重建恢復。
- 儲存期間停用重複送出，成功後才離開頁面；失敗時保留輸入內容並顯示可重試訊息。
- 偵測表單是否已修改，離開前提供「繼續編輯」與「捨棄變更」。
- 刪除確認視窗留在編輯頁上；刪除成功後回主畫面並提供 Snackbar 復原。
- 改用 Material 3 DatePicker 與 TimePicker，保持深淺色與主題一致。
- 補上欄位說明與即時驗證，例如名稱必填、名稱長度上限與錯誤訊息。

**預期效益**

- 避免草稿及編輯脈絡意外消失。
- 讓使用者明確知道資料是否儲存成功。
- 降低誤刪與重複送出的風險。

### 3. 強化空狀態、載入狀態與回饋（P1）

**現況與問題**

- DataStore 尚未完成讀取時，畫面可能短暫顯示「沒有紀念日」與預設主題，無法區分載入中與真正空資料。
- 新增、更新、刪除與設定變更缺少一致的成功或失敗回饋。
- 空狀態不可捲動，在橫向、小螢幕或極大字體下可能超出畫面。

**建議方案**

- UI 狀態明確區分 Loading、Content、Empty 與 Error。
- 寫入失敗時用 Snackbar 顯示原因與重試操作；刪除成功提供復原。
- 空狀態使用可捲動容器，並保留清楚的主要行動按鈕。
- 初次使用可用簡短引導說明「建立事件、設定提醒、加入 Widget」三個核心價值。

### 4. 支援響應式版面與大字體（P2）

**現況與問題**

- 分類與主題選項固定為三欄，窄螢幕與大字體可能裁切。
- 顯示模式選項限制單行且直接裁切文字。
- 紀念日卡片使用固定高度色條與固定日期欄寬，文字放大後版面可能不協調。
- 平板與橫向模式仍使用手機單欄版面。

**建議方案**

- 將選項改為 `FlowRow` 或可自動換行的 Chip，不固定欄數。
- 允許顯示模式文字換行，或改用垂直 RadioButton 清單。
- 移除卡片裝飾元素的固定高度，讓其跟隨內容尺寸。
- 依 Window Size Class 提供單欄、雙欄或列表與詳情並列版面。
- 在平板限制表單最大寬度，避免欄位過度拉伸。
- 驗證字體倍率 1.0、1.3、1.5 與 2.0，以及橫向顯示。

### 5. 補足無障礙語意與色彩對比（P1-P2）

**現況與問題**

- 色彩選項主要以色塊與勾號表示，缺少色彩名稱、選取狀態與螢幕閱讀器描述。
- 部分區域存在外層與內層都可點擊的重複操作節點；自訂色預覽也可能呈現為可點擊但沒有作用。
- 自訂事件顏色被直接用於文字，亮黃色或青色在淺色背景上可能對比不足。
- 目前沒有大字體、TalkBack 或對比測試。

**建議方案**

- 為色彩選項加入可讀名稱、`selected` 狀態與目前選擇描述。
- 合併重複的點擊語意，移除沒有行為的 clickable。
- 自訂色優先用於裝飾色條或圖示；主要文字使用主題的高對比前景色。
- 自動計算文字與背景的安全配色，App 與 Widget 使用一致規則。
- 互動元件維持至少 48dp 觸控範圍，並加入 TalkBack 操作檢查。

### 6. 統一文案、日期與在地化（P2）

**現況與問題**

- 大部分畫面與 Widget 文案直接寫在 Kotlin 程式中。
- 日期格式偏向固定台灣格式，數量也未使用複數資源。
- App 與 Widget 各自維護分類及重複規則文案，容易不一致。

**建議方案**

- 將所有使用者可見文字移至 `strings.xml`，數量文案使用 plurals。
- 日期、時間與數字依裝置 Locale 格式化。
- App 與 Widget 共用分類、重複規則及倒數文案資源。
- 先完整支援繁體中文，再保留英文等其他語系的擴充能力。

## 功能優化建議

### 7. 修正資料安全與儲存可靠性（P0）

**現況與問題**

- 所有紀念日以單一 JSON List 存在 Preferences DataStore。
- 任一資料解析失敗時，目前流程會回傳空清單；後續寫入可能覆蓋原始資料。
- 資料沒有 schema version、migration、損壞備份或使用者可見錯誤。
- 寫入結果沒有傳回 UI。

**建議方案**

- 為持久化格式加入 schema version 與明確 migration。
- 解析失敗時保留原始內容，不可自動以空清單覆寫。
- 對每筆紀念日分別驗證，讓單筆異常不影響其他資料；資料量增加後可評估改用 Room。
- Repository 回傳明確的成功或錯誤結果，並加入錯誤記錄與復原流程。
- 寫入採原子性策略，並補上損壞資料、未知 enum 與 migration 測試。

### 8. 修正日期型事件的倒數語意（P0）

**現況與問題**

- 未指定時間的事件文件宣稱「以日期為單位」，但實際仍可能以目標日午夜與現在的 duration 顯示小時，例如今天中午可能把明天顯示為「剩下 12 小時」。
- 天數換算採固定 24 小時，跨日光節約時間時不等同日曆日。
- 七天內醒目提示也使用固定毫秒數判斷。

**建議方案**

- 日期型事件以 LocalDate 與日曆日差計算，顯示「今天、明天、剩下 N 天」。
- 有指定時間的事件才用 Duration 顯示天、時、分。
- 近期事件判斷改用日曆日期，而不是固定毫秒常數。
- 補上午夜邊界、DST、不同時區及日期型／時間型事件測試。

### 9. 實作真正的通知提醒（P1）

**建議能力**

- 每筆紀念日可開關提醒。
- 提供「事件當天、提前一天、提前一週、自訂」等提醒時間。
- 支援同一事件多個提醒，並清楚顯示下一次排程時間。
- Android 13 以上在需要時請求通知權限，拒絕後提供設定引導。
- 建立 NotificationChannel，通知點擊後直接開啟對應事件。
- 新增、修改、刪除、重新開機、時區變更與系統時間變更後重新排程。
- 使用 WorkManager 處理可延遲工作；只有產品需求必須準點時，才評估 AlarmManager 與精準鬧鐘限制。
- 設定頁提供「傳送測試通知」，協助使用者確認權限與系統限制。

**設計原則**

- 不應在 App 啟動時立即要求通知權限；先讓使用者開啟某筆提醒，再說明權限用途。
- 對無指定時間的事件提供合理預設，例如當地時間上午 9:00，並允許修改。
- 清楚說明省電模式可能造成的延遲，不承諾系統無法保證的精準度。

### 10. 提供備份、匯出與匯入（P1）

**建議方案**

- 使用 Android Storage Access Framework 匯出具版本的 JSON 備份，不要求廣泛儲存空間權限。
- 匯入前顯示事件數、格式版本與衝突摘要。
- 衝突可選擇略過、覆蓋或建立副本，完成後顯示結果統計。
- 匯入前自動建立可復原備份，避免錯誤操作破壞現有資料。
- 在設定頁清楚說明本機資料與 Android 系統備份政策。

### 11. 強化桌面小工具（P1-P2）

**現況與問題**

- 點擊 Widget 只會開啟 App，不能進入目前顯示的事件。
- 最小高度要容納多行文字，部分 Launcher 或大字體下可能裁切。
- 不同 Widget 尺寸都顯示同樣資訊，沒有尺寸適配。

**建議方案**

- 點擊有資料的 Widget 直接開啟對應紀念日；空狀態直接前往新增頁。
- 在 `onAppWidgetOptionsChanged` 依尺寸切換版面：小尺寸顯示名稱與天數，大尺寸顯示日期、分類或多筆事件。
- 加入重新整理動作與上次更新時間，但避免造成頻繁背景工作。
- 提供接近實際內容的 Widget 預覽，並檢查深色、淺色及高對比。
- 評估以 Glance 重構的成本與收益，不為重構而重構。

### 12. 新增搜尋、篩選、排序與管理能力（P1-P3）

**建議方案**

- 支援名稱即時搜尋。
- 支援分類、即將到來、已過期、含提醒等篩選條件。
- 提供下一次日期、建立時間與名稱排序。
- 為已過期的一次性事件提供封存，而不是只能刪除。
- 資料量較大後可加入批次封存與批次刪除。
- 進階版本可加入月曆檢視，但應在搜尋與篩選穩定後再實作。

### 13. 新增分享能力（P2）

**建議方案**

- 透過 Android Sharesheet 分享簡潔文字，例如「距離旅行還有 12 天」。
- 可選擇是否包含日期、時間與分類，避免無意揭露私人資訊。
- 後續可提供品牌化圖片卡片，但文字分享應先完成且保持可存取性。

### 14. 改善時區設定（P2）

**現況與問題**

- 「固定時區」只會鎖定建立當下的裝置時區，無法主動選擇其他地區。
- 介面顯示 raw zone ID，對一般使用者不夠友善。
- 無效時區會靜默退回裝置時區，可能隱藏資料問題並改變實際到期時間。

**建議方案**

- 提供可搜尋的時區選擇器，顯示城市、UTC offset 與 DST 說明。
- 儲存 IANA zone ID，畫面則顯示在地化名稱。
- 無效時區應顯示資料需修正，不應無聲改用裝置時區。
- 在編輯頁即時預覽事件在目前裝置時區的實際發生時間。

### 15. 補強測試、發布與隱私品質（P1-P2）

**建議方案**

- Repository 測試涵蓋讀寫、損壞 JSON、未知 enum、migration 與 I/O 失敗。
- Compose UI 測試涵蓋空狀態、新增、編輯、刪除、未儲存變更與語意。
- 裝置測試涵蓋通知排程、Widget、系統時間及時區變更。
- 建立 CI 執行單元測試、Lint、prerelease build 與必要的 UI 測試。
- 正式發布前更換 `com.example.*` 套件名稱、建立正式簽章、自動化版本與可重現 Build ID。
- 明確定義 Android Auto Backup／Data Extraction 規則，並讓隱私說明與實際行為一致。

## 建議執行順序

### 第一階段：正確性與資料安全

1. 防止解析錯誤清空資料。
2. 修正日期型倒數與 DST 邊界。
3. 建立儲存結果、載入與錯誤狀態。
4. 保存編輯草稿並保護未儲存變更。
5. 改善刪除流程並提供復原。

### 第二階段：完成「提醒」核心價值

1. 實作通知權限、排程與重新排程。
2. 加入每筆事件的提醒設定與測試通知。
3. 提供匯出、匯入及資料復原。
4. 加入搜尋與主要篩選功能。
5. 讓 Widget 可深層連結至事件。

### 第三階段：可用性與品質

1. 響應式版面、大字體與 TalkBack。
2. 字串資源、Locale 日期格式及共用文案。
3. Widget 尺寸自適應與預覽。
4. 完善自動化測試與 CI。
5. 完成正式發布與備份政策。

### 第四階段：擴充功能

1. 分享文字與圖片卡片。
2. 封存及批次管理。
3. 月曆檢視。
4. 視需求評估跨裝置同步。

## 建議衡量指標

- 資料解析或寫入錯誤不會造成既有資料被覆蓋。
- 新增／編輯成功率與寫入錯誤率可被測試或記錄。
- 通知權限開啟率、提醒排程成功率及通知點擊率。
- 從主畫面找到指定事件所需時間與操作次數。
- TalkBack 核心流程可完成率，以及字體倍率 2.0 下的版面通過率。
- Widget 點擊進入正確事件的成功率。
- 單元測試、Lint 與建置在 CI 的穩定通過率。

## 範圍控制建議

- 先確保資料安全、日期正確及通知可靠，再投入月曆、圖片分享或雲端同步。
- Room、Navigation Compose、Glance 等技術重構應由具體需求驅動，不宜與所有功能同時改寫。
- 每一階段都應保留現有資料相容性，並以 migration 測試驗證升級路徑。
